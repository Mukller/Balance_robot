# Руководство по слежению по линии (Line Following)

## Что произойдёт

После загрузки основного скетча `esp32_robot_main.ino` робот автоматически:

1. **Калибровка гироскопа** (3 попытки, 2.5 сек каждая) — РОБОТ НЕ ДВИГАЙТЕ
2. **Тест моторов** (1 секунда вращения)
3. **STATE_IDLE** (5 сек) — балансировка на месте
4. **STATE_STRAIGHT** (2 сек) — прямое движение вперёд
5. **STATE_LINE_FOLLOW** — слежение по линии + балансировка (АВТОМАТИЧЕСКИ)

## Подготовка к линии

### Шаг 1: Разберитесь с датчиками линии

Пины датчиков:
- **GPIO 34** (Sensor 0, LEFT) — ✅ РАБОТАЕТ (АЦП с pull-up)
- **GPIO 35** (Sensor 1, L-CENTER) — ⚠️ МОЖЕТ НЕ РАБОТАТЬ (input-only)
- **GPIO 36** (Sensor 2, CENTER) — ⚠️ МОЖЕТ НЕ РАБОТАТЬ (input-only)
- **GPIO 39** (Sensor 3, R-CENTER) — ⚠️ МОЖЕТ НЕ РАБОТАТЬ (input-only)
- **GPIO 32** (Sensor 4, RIGHT) — ✅ РАБОТАЕТ (АЦП с pull-up)

**Проблема**: GPIO 35/36/39 — input-only пины без встроенных подтяжек резисторов.

**Решение**: 
- Добавить внешние pull-up резисторы **10кОм к 3.3V** на пины 35, 36, 39
- ИЛИ использовать только датчики 0 и 4 (крайние) — они работают и системе достаточно

### Шаг 2: Найдите чёрную линию

Нужна:
- Контрастная чёрная линия на белом фоне
- Ширина линии: 20-40mm
- Поверхность: гладкая (бумага, линолеум, стол)

### Шаг 3: Загрузите тестовый скетч калибровки

Перед первым использованием **обязательно** откалибруйте датчик:

```
main/test_line_calibrate/test_line_calibrate.ino
```

**Что делает:**
- Непрерывно читает значения со всех 5 датчиков
- Отслеживает min/max значения
- Показывает какие датчики "застревают" (не меняют значения)

**Как использовать:**
1. Загрузите `test_line_calibrate.ino`
2. Откройте Serial Monitor (115200 baud)
3. Медленно проводите датчик над разными поверхностями:
   - Чистый белый стол → значения ~500
   - Чёрная линия (скотч) → значения ~3500
   - Отметьте какие датчики НЕ меняют значения (застревают)
4. Подождите 30 сек и посмотрите [MIN] и [MAX]

Пример вывода:
```
[RAW]  450 450 450 450 450 | [MIN] 450 450 450 450 450 | [MAX] 3200 3200 3200 3200 3200
```

## Запуск слежения по линии

### Сценарий 1: Все датчики работают (оба pull-up резистора установлены)

1. Загрузите `esp32_robot_main.ino`
2. Откройте Serial Monitor (115200 baud)
3. Дождитесь сообщения: `[BALANCE] Balancing for 5 seconds...`
4. **Поднимите робота вертикально** и держите неподвижно
5. Через 5 сек робот перейдёт в `STATE_STRAIGHT` и начнёт двигаться вперёд
6. Через 2 сек робот перейдёт в `STATE_LINE_FOLLOW` и начнёт следить по линии

**Вывод**: Будет печатать каждые 100мс:
```
[DBG] A:-5.23° Bal:2 Spd:0 Out:1 M1:0 Str:-15 St:2 [Line] 10 20 50 30 15 | Error:-20
```

Где:
- `A` = Angle (угол наклона)
- `Bal` = Balance output (команда балансировки)
- `Str` = Steering (руление влево-вправо)
- `St` = State (0=IDLE, 1=STRAIGHT, 2=LINE_FOLLOW, 3=STOPPED)
- `[Line]` = значения 5 датчиков (0-200 шкала)
- `Error` = положение линии (-200 = левый край, 0 = центр, 200 = правый край)

### Сценарий 2: Центральные датчики не работают (без pull-up резисторов)

Система **автоматически** переключится на режим "edge-only":
- Будет использовать только датчики 0 и 4 (крайние)
- Будет видеть линию если она под одним из крайних датчиков
- Может быть менее чувствительна к малым отклонениям

## Настройка пропорционального коэффициента

В `LineFollower.cpp:109` установлен `Kp_line = 0.5`.

Это означает: Error ×0.5 = steering команда

- **Увеличить** (0.7, 0.8) → более агрессивное руление
- **Уменьшить** (0.3, 0.2) → более мягкое слежение

## Диагностика проблем

### Робот не балансирует в STATE_IDLE

**Проверить:**
1. Датчик гироскопа откалиброван? (должны быть сообщения `[CALIB] Attempt 1/3...`)
2. Робот в вертикальном положении при включении?
3. Провод I2C подключен (GPIO 21/22)?

### Робот не едет в STATE_STRAIGHT

**Проверить:**
1. Моторы работают? (должно быть `[TEST] Motor spin for 1 second...`)
2. Драйвер TMC2209 имеет питание (красный LED)?
3. EN pin на LOW (GPIO 12 подключен к GND)?

### Робот не следит по линии в STATE_LINE_FOLLOW

**Проверить:**
1. Запустить `test_line_calibrate.ino` и убедиться что датчики видят разницу между белым и чёрным
2. Линия достаточно контрастная? (чёрное на белом)
3. Датчики правильно отцентрированы над линией?
4. При необходимости добавить pull-up резисторы на GPIO 35/36/39

### Serial вывод показывает `[Line] 0 0 0 0 0`

Датчики не видят линию вообще:
- Линия на самом деле есть?
- Датчики над линией?
- Свет достаточный?
- GPIO 35/36/39 нуждаются в pull-up резисторах?

## Гайд по Pull-up Резисторам (для продвинутых)

Если центральные датчики не работают, нужны внешние pull-up резисторы:

```
3.3V ────[ 10кОм ]────┬──── GPIO 35 (Sensor 1)
                      └──── GND (через датчик)

3.3V ────[ 10кОм ]────┬──── GPIO 36 (Sensor 2)
                      └──── GND (через датчик)

3.3V ────[ 10кОм ]────┬──── GPIO 39 (Sensor 3)
                      └──── GND (через датчик)
```

Или максимально просто: **используйте только датчики 0 и 4** (GPIO 34 и 32), система будет работать.

## Что дальше

После успешного слежения по линии можно:
1. Опустить максимальную скорость в STATE_LINE_FOLLOW (сейчас throttle=150)
2. Настроить Kp_line коэффициент для более гладкого слежения
3. Добавить точку разворота (например, если строка обнаружена на краю)
4. Перейти к более сложным трассам
